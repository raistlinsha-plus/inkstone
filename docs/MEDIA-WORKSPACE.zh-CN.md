# 图片、独立脑图与空间目录的存储设计

## 手动布局与自动排版（构建 10217）

将节点拖入空白处时，Inkstone 在文件注释里保存相对于自动布局的位置。重新打开时，画布将分支和子节点一同定位。选择「自动布局」可清除手动位置。将节点放到另一个节点上时，Inkstone 更新文本中的父子关系或同级顺序。其他 Markdown 或 Mermaid 查看器可以按各自的规则排版。

## 分支折叠与顺序（构建 10215）

折叠与展开控制画布展示的层级，源文件和导出的 SVG 均保留全部节点。通过节点菜单上移或下移会把整条分支写回同一份源文件，保存后可在源码视图核对节点顺序。

## 独立脑图如何保存（构建 10214）

在 `.mindmap.md` 或支持的 Mermaid `.mmd` 中，节点文字、分支顺序与父子关系都写回当前文件。拖动分支会同时移动其子节点。画布按层级重新排版。选择「彩色分支」或「墨线」会写入对应格式的注释，恢复默认「青竹」时移除样式标记。复杂 Mermaid 语法保留原生预览和源码入口。普通笔记的大纲根据文档结构生成。

本地构建 10211 将图片原件、可显示的预览和可检索的文本放在同一个资料 ID 下。每份图片资料包含一篇带类型标记的 Markdown 说明、一份原始格式的二进制文件和一张最长边 3200 像素的 JPEG 预览。原件按原始字节保存，HEIC/HEIF 通过 macOS ImageIO 解码。文字识别使用 Apple Vision；导入本身不调用模型。空间内使用原图的内容指纹判断重复导入。

图片的文字说明沿用文档保存、索引和引用流程。用户主动发起视觉问答时只发送该图片的预览与问题。用户保存模型描述后，检索才能使用该段文字。模型服务和鉴权复用问答配置，视觉和生图模型 ID 可分别指定。这里的图片检索依赖文本，未建立图像向量索引。可用「导出原图」取得原始文件。

独立脑图使用带有 .mindmap.md 后缀的 Markdown 文件，标题和无序列表表示节点层级。画布改动回写同一份文本，普通编辑器也能读取。项目目录使用逻辑路径和资料 ID 组织资料，移动文件夹内的资料不会改变底层托管路径。空间置顶、归档和目录映射写在本机资料库数据库中。归档是可撤销的整理操作，恢复后可继续打开资料。
