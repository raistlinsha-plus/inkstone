# Inkstone v0.7 开发候选交付

2026-11-05。当前应用版本为0.7.0-rc.1；最近公开源码版本仍为v0.6.6。本轮在生产代码中实现会话式知识问答与三角色成长，未将离线原型当作实际模型功能。正式发布前保留自然使用、原生无障碍及素材动作签收门槛。

## 已实现

- 独立assistant.sqlite3：会话、固定空间/单文档范围、草稿、轮次分支、回答候选、来源快照、重命名、归档、删除、Markdown/JSON导出及重开恢复。
- 侧栏/展开问答共享会话；真实生成事件按帧合并，支持停止/重试/候选切换；旧候选复制/保存/插入保持自己的来源身份，不误用最新回答。
- 追问只从重新校验的上一轮来源身份解析对象；当前所问属性单独约束证据。历史问题的旧属性和历史AI断言不能让新缺项获得证据资格；不新增规划模型调用。
- 独立companion.sqlite3：墨团/砚舟/知微、初遇/相识/同行、九章、选择、形象与CG相册、经历卡、偏好、关闭/收起、导出/清空。
- 实际保存之后才有后端凭据，用户明确确认后单独写经历；同对象同日去重、每日最多两条；3经历/2不同日和8经历/5不同日及前章/修订条件。持久待处理与奖励分事务，失败不回滚工作正文。
- 9张阶段形象与6张CG候选文件已接入，均记录hash/尺寸/来源；是静态像素水墨候选插画，尚未完成严格逻辑像素网格及最终动画签收。
- 完整备份format2纳入两个辅助库，冻结/排空写入、WAL一致快照、语义及指纹校验、最终源重检；兼容读取format1旧包，明确说明旧包缺少角色或会话数据，不伪造恢复内容。catalog/index仍schema3。

## 检查与候选制品

冻结代码的完整门槛通过：47个前端文件260项、Rust164通过/6项显式远程忽略、工具检查、44项原型检查，以及类型/Worker/生产前端构建/文档。内容指纹续跑核对输入、环境与产物；不重复不受影响的付费请求。首次集成检查在追问证据策略修订期间命中旧预期断言，原失败日志保留；修订后的针对性及完整集成已通过，复用检查核对输入/环境/输出指纹，不把局部检查冒充完整通过。

浏览器使用实际React App配独立合成IPC，并非Rust后端/真实模型集成。已走通多轮、每轮来源、停止、草稿、重命名和重开；侧栏与展开共六种窗口组合无横向溢出，960×640答案区约190/230px，发送可见。原生桌面控制先超时、后报告锁屏，不能由浏览器结果宣称真实WebKit编辑、拼音候选或VoiceOver通过。

## 预发布边界

- 当前支持整个空间或固定单文档，任意文档集合选择尚未实现；明确指代无法安全解析时会保守澄清，抽象改写仍可能漏答。
- 角色经历卡暂未分页；已有经历后的时区修改暂不开放，避免历史日期被重分；固定时区由首次启用时明确设置。
- 静态插画候选已具备阶段/场景区分，sprite动作、严格限色重绘、正式资源许可签收及五个不同使用日的自然试用仍未完成。
- 本地临时签名，未Developer ID/公证或跨机安装验收；不承诺更新后不会再次要求Keychain授权。
- 原生界面、中文候选与读屏另列；真实API以实际冒烟报告为准，不把历史v0.6.6结果算作本轮测试。
- 本轮不移动v0.6.6标签、不上传新Release；开发候选与正式公开发行分别验收。

源码开发主线位于独立Inkstone仓库；旧内部仓库保留历史与文档，不合并上传私人历史。生产资料库不由浏览器夹具读取，应用内项目资料同步继续遵照用户决定暂缓。

使用已配置AIhubmix/gpt-4.1-mini，仅发送合成资料。实际2次HTTP200，首问和指代追问事实/引用逐项复核，第三问缺预算在本地拒答、无模型调用。没有重复向量/重排评测；三题同作者已见样本，不称总体准确率。原始失败/请求预算/结果和复核分别留存，详见[冒烟结果](../evals/v0.7/RESULTS.md)。评测器不读Keychain；外层仅在内存复用用户授权同源服务条目，密钥不进入文件。

## 建议试用顺序

1. 正常退出旧应用，再打开本轮候选。保持现有模型设置，先建立一个合成文档空间。
2. 问答展开→首问→追问→来源预览→保存新文档→重开会话；缺少资料时应拒答或澄清。
3. 开启墨团→阅读初遇→保存一份真实修改的合成笔记→明确确认经历→查看卡片；普通保存和提问不增长。
4. 查看三角色/故事/相册/偏好、收起与关闭，删除或导出前核对范围。达到成长条件后主动开章，未解锁不可强行跳级。
5. 生成包含会话与角色的备份并校验，在新目录恢复预演；旧包会明确提示缺少哪些新域。
