# v0.6.5 GitHub公开准备评估

2026-11-02。结论：**具备整理成源码技术预览的基础；当前工作目录及全部历史不建议直接整体公开，正式稳定安装包尚未达到公开发行条件。** 已准备独立的无历史公开源码快照与只读CI配置，没有创建远程仓库、上传文件或push。最终快照的本地复现结果在交付记录列出；GitHub托管CI的首次运行仍未验证。

## 产品与工程

- 主链路已具备：复制导入文档空间、Markdown正文/源码与结构块、索引、混合检索/重排、富内容回答、引用定位和备份恢复。角色生产能力仍未交付，独立原型明确分开。
- v0.6.5真实四路评测发现并修复“重排高分直接授予答案证据”的缺陷；保持hash/身份/范围检查和原关键词门槛。新增32题的原句入上下文比例79.2%，仍未达85%；跨文档拒答、同作者出题和两项标签勘误限制了质量结论。详见[评测结果](../evals/v0.6.5/RESULTS.md)。
- 解锁后已实际完成最终隔离包约960×640双侧栏/工具栏、保存往返重开，生产包0.6.5冷启动恢复项目空间及新增文档。中文候选、VoiceOver、跨机器与长期内存/性能仍未验收，不能由自动测试或启动探针代替。启动早期短暂显示欢迎空态后恢复，建议后续补加载占位。
- 当前代码仍有较大的App/lib编排入口，维护风险未消失；本轮复用共享排序/上下文函数，新增评测和预算单独成模块，没有把全部逻辑继续加入App。

## 公开源码准备

已添加CONTRIBUTING、SECURITY、问题模板、macOS只读CI和公开README。CI使用GitHub官方当前支持的`macos-15` ARM runner、固定Node/npm/Rust基线，官方checkout/setup-node动作固定提交SHA，不注入模型凭据、不运行ignored真实API测试。它编译本地临时签名的.app，不自动发布或上传。runner依据[GitHub文档](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。工具链版本记录在toolchain.json，Rust版本可核对[官方发布记录](https://blog.rust-lang.org/2026/10/15/Rust-1.99.1/)。

`node scripts/export-public.mjs --out <全新目录>`按明确白名单复制生产源码、合成语料、原型、许可和公开说明，生成文件SHA清单；交付包用`check-public-docs.mjs --integrity`核对原始指纹，日常CI只检查文档链接，允许贡献者正常修改源码，不把发行快照清单变成修改禁令；排除.git、Inkstone项目、历史内部文档、用户截图/日志、应用数据、凭据、构建缓存和本机镜像配置。不会覆盖已有目录，不替用户初始化或推送仓库。公开快照使用独立文档/清单检查，内部项目继续走原副本一致性检查。包锁改用官方npm下载地址，未因此更新npm生产依赖版本，Vitest及其测试子包另作4.1.11→4.1.12安全补丁升级。

## 敏感信息与隐私

Gitleaks 8.30.1来自官方发布并核对checksum。初轮已扫描当前受跟踪及新源码、13次Git历史提交；交付前对最终公开快照及含本版提交的历史另行复扫；源码/历史初查为0项密钥发现；最终公开快照原始扫描标记2项generic-api-key，实际均为public-snapshot.json中mock-api.py/credentials.rs的SHA-256。逐文件重新计算后确认与清单一致，作为明确复核的误报保留，真实凭据发现为0；没有添加全局忽略来隐藏标记。该结果不等于发现所有秘密；本机目录名、用户文档截图等隐私不是密钥规则能完整识别的。原目录有个人机器路径和历史产品截图，所以推荐审阅后的无历史快照，不把扫描无命中当作全历史隐私授权。

没有把用户API Key、Mac口令、应用数据或真实资料纳入公开快照。模型评测只发送合成资料。仍需仓库所有者在GitHub启用私密漏洞报告、secret scanning和分支保护；这不在本轮本地配置等同已开启的范围内。公开issues提醒用合成最小复现，禁止上传凭据和私人备份。

## 许可与依赖

项目Apache-2.0、NOTICE和第三方清单已存在。当前本机已获取依赖清单792项（443 npm、349 Cargo），没有未识别的许可表达；khroma缺失的metadata由其随包MIT文本头确认。许可不全是MIT/Apache：含MPL-2.0、Unicode等，原声明和未修改源码下载地址保留。

**28项依赖没有随已获取包提供可复制的独立本地许可文本**，包括部分平台binding、objc2系列、selectors等；清单保留实际空项，没有伪造版权声明。需从对应上游精确版本补齐必要声明并复核，再把含第三方二进制的安装包作为正式分发物。源码自身的Apache许可、锁文件及上游链接已经明确，但本轮不出具整套第三方分发的法律合规结论。其他平台的未获取依赖也不能当作已审查。

- 官方npm audit（生产依赖与含开发依赖的全量扫描）最终均为5个low、0 moderate/high/critical。开发工具曾命中2个moderate包记录，已通过Vitest 4.1.12补丁清除；剩余5个low，由一项KaTeX条件性公告沿依赖链传播，并非5个独立漏洞。编辑器math功能关闭，仍不据此声称所有相关渲染路径完全不可达；保持renderer隔离和清洗，未放宽CSP。见[GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7)。修复需评估KaTeX/上游兼容升级，没有强制跨主版本覆盖。
- Cargo.lock通过OSV查询整个锁定图，包含其他平台和开发依赖。发现zip旧版本公告后已升级至**9.0.5**并适配错误返回的文件名API。应用继续自有路径/hash/符号链接检查、私有文件权限与新目录恢复，不调用库的任意解压入口。没有把“我们未调用危险函数”当作继续保留旧版本的唯一依据。参考[zip修复公告](https://github.com/advisories/GHSA-m665-v7pm-7grj)。
- 剩余fxhash/proc-macro-error维护状态、glib其他目标和zstd/zstd-safe公告继续记录。macOS正常依赖图没有glib；zstd来自jieba的固定字典压缩/解压链，而非产品接收任意用户zstd流，相关上下文复用/unsafe前提仍需逐项验证和上游升级。不能把锁图所有命中直接当作本机可利用漏洞，也不能因使用路径受限就全部标为已修复。检查源为[OSV](https://osv.dev/)，时间和完整命中保存在本机检查报告。

## 发布建议

1. 源码以`v0.6.5 technology preview`定位，优先使用无历史快照，先审阅公开文件清单并在真实GitHub runner跑绿；没有远程仓库地址时不替用户选账号、创建或推送。
2. 宣传可用的编辑/空间/检索能力，同时公开新题质量未达标、原生检查待办和已知依赖情况；不要使用“成熟稳定”“全平台”“已全面核验答案”等表述。
3. 正式安装包发行前补齐许可文本、处理/确认剩余依赖公告、完成最终原生与跨机验收、Developer ID与公证，并启用维护/漏洞响应入口。无需关闭用户锁屏、清空钥匙串或保存Mac登录口令来降低开发等待。
4. 后续RAG评测先修正标签另建新版本，至少增加独立审阅的跨文档与不足题；保持引用与证据门槛。角色技术预览可独立推进，不能借角色语气掩盖证据不足。
