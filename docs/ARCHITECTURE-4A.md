# Inkstone 4A 架构 · v1.2.0-beta.1

v1.4.0 中，图片原件、OCR 和保存的描述分别管理。视觉请求校验预览与服务信息。生图的远程请求与本机保存分开，用户确认目标后将结果作为图片资料写入空间。[稳定版交付](DELIVERY-v1.4.0.md)

## 图片进入对话与资料库

每轮通过空间和文档 ID 解析图片。OCR、描述和像素各有明确用途。像素发送需要核对预览哈希及目的模型。生图经原生端处理，预览留在窗口，用户保存后走资料库现有的图片导入、OCR 和引用流程。

Inkstone 是个人 Mac 上的文档工作台。一个**空间**可以收集多个目录中的文档副本。用户在空间中写作，从问答的引用回到原文，也可以把授权的文档整理成 Wiki。下面从业务、应用、数据和技术四个角度说明这条路径。

1.0 候选版增加本机外部工具入口。桌面端管理独立连接及其空间授权；CLI 以只读方式打开现有资料和关键词索引，读取时再次核对连接、版本与行号。Wiki 用编纂输入追踪派生资料的范围，撤回时在写事务内复查影响快照。[外部读取约定](EXTERNAL-TOOLS.zh-CN.md) · [RC.4 交付与验证](DELIVERY-v1.0.0-rc.4.md)

## 1.2 集成候选

业务上，用户从对话中挑出承诺，选定笔记后保存。应用上，消息、正文、任务清单和日历通过文档与任务 ID 定位到同一行。数据上，标题、勾选和排期存在 Markdown；按内容哈希缓存的 SQLite 任务表可从笔记重建，私有聊天来源和逐回答请求摘要则在会话库版本 5 中保存。技术上，Rust 负责原文校验、文件写入和请求统计，编辑器与本地化界面负责选取和呈现。旧笔记和普通勾选项可继续使用。[集成与迁移设计](design/v1.2-integration.zh-CN.md)

## 任务、日历与 Markdown

任务和日历是两个独立工作区。每个空间用文档 ID 记住快速添加的默认任务笔记，首次确认添加时创建。改名后继续写入原笔记，移入回收站后再次添加会创建替代笔记。任务清单、日历的全天标记与时间块通过同一条 Markdown 任务读写，拖动执行时段只更新开始和结束时间。

## 业务架构

| 用户任务 | 边界和结果 |
| --- | --- |
| 收集和写作 | 导入为受管理副本，保留来源关联。修改副本保存到空间；原件有变化时由用户比较并决定如何更新。高级外部目录模式直接读写所选目录。 |
| 编辑与排期 | 正文、源码与分栏使用同一份 Markdown。JSON、Mermaid、脑图、日程和图表通过专用内容块呈现。日历修改写回所属文档。 |
| 查资料与提问 | 文档侧栏在一篇文档或当前空间内提问。独立问答可以直接对话，也可以使用一个空间、该空间内选定的文档或会话附件。回答保存后仍能核对受管理文档引用。 |
| 维护 Wiki | 用户为一个空间选择主题、来源与维护策略。整理产生可审阅的页面变更，允许的常规更新可自动生效。高风险变更可以退回或仅发布已核验摘录。 |
| 书房陪伴 | 三位角色在页边陪读，窄窗收成书签。用户在文档保存成功后预览并确认经历，累积有效经历与使用日后可解锁章节、形象和相册。 |

## 应用架构

桌面壳运行 React 工作台。编辑器负责选区、输入与渲染，Rust 负责文件、数据库和服务请求。三条跨模块路径解释了界面状态如何成为持久数据。

1. **从保存到经历。** 文档会话检查修订并保存。受管理文档的有效修改会产生限时保存凭据。用户打开页边卡片并确认后，同伴模块校验凭据、去重并记录。每天最多两条，同一文档当天一次。取消或确认后可回到原编辑选区。问候、拖动和问答完成动画只改变界面状态。[文档会话](../src/document) · [同伴前端](../src/companion) · [同伴后端](../src-tauri/src/companion)
2. **从提问到引用。** 问答模块根据本轮范围取得候选。原文 BM25 和可选向量用 RRF（按名次融合）合并；已发布 Wiki 可帮助定位原始片段。可选重排调整优先级。送入生成前检查文档范围、版本、证据和上下文预算。RC.4 可按小问核对引文。用户单独开启模型辅助核对后，Rust 会重新验证返回的原句及当前资料版本。获得授权的网页检索单独排序，只将成功读取的网页摘录纳入证据。历史保存本轮来源快照，原文变更后可以区分当时的摘录与现行文档。[问答编排](../src-tauri/src/assistant_runtime.rs) · [检索](../src-tauri/src/retrieval.rs) · [证据检查](../src-tauri/src/evidence.rs)
3. **从资料变更到 Wiki 发布。** 整理任务按授权范围读取输入、提出增量变化、保存来源与版本。审阅界面展示基线差异、逐项结论、来源及原句。发布和问答召回分别复核当前授权与原文版本。撤回来源前预览涉及的主题、待审项和历史版本。确认后清除依赖被撤来源的派生记录，保留原始文档。[Wiki 后端](../src-tauri/src/wiki.rs) · [逐项审阅](../src-tauri/src/wiki/claim_review.rs)

## 数据架构

| 数据与当前 schema | 保存什么 | 恢复依据 |
| --- | --- | --- |
| 空间文件、catalog 4 | UTF-8 正文、附件、历史，以及空间和文档的稳定 ID、相对路径和状态 | 空间文件和目录元数据一起备份 |
| 检索索引 3、日历缓存 1 | 分块、全文与向量检索数据、日历汇总 | 可从源文档重建。重新生成远程向量可能产生服务费用 |
| assistant 5 | 会话、草稿、分支、回答候选、引用快照、会话附件与问答偏好 | 随便携备份保存 |
| Wiki 2 | 空间授权、提案、已发布页面、来源、版本与审阅记录 | 随包含 Wiki 的备份保存 |
| companion 1 | 角色进度、经历、确认凭据与待处理记录 | 随便携备份保存。停靠边和相对高度另存为 WebView 本机布局偏好 |
| 应用私有凭据文件 | 按服务用途和完整地址绑定的密钥。旧版钥匙串项可在设置中单独导入 | 当前用户可读写，跨设备时单独配置，文档便携备份排除此文件 |

便携备份在写入协调下取一致快照并校验。存在 Wiki 库时生成格式 3，否则生成格式 2；恢复预演写入新目录。本机原位升级还会保存升级前快照，供回退使用。[备份实现](../src-tauri/src/maintenance.rs) · [本机升级](LOCAL-INSTALLATION.md)

## 技术架构

Tauri 2 在 macOS 系统 WebKit 中运行界面，通过 IPC 将受限命令交给 Rust。SQLite 在应用进程内工作。普通编辑、关键词检索、阅读已保存内容和同伴动作可在本机进行。配置向量、重排、聊天、Wiki 整理或自动联网后，对应操作会将查询或选定内容发给配置的服务。阅读已有 Wiki 与重新调用模型整理是两次不同操作。

同伴只订阅本轮文档问答的状态，显示陪读和就绪动作；这条反馈路径不会发起模型请求。语义检索、模型调用和证据核验各有独立职责，回答准确性仍需结合原文判断。构建版本、外发内容和测试边界见[技术栈](TECH-STACK.md)、[配对评测](../evals/v1.0/rc4/README.md)与[本版交付](DELIVERY-v1.0.0-rc.4.md)。
