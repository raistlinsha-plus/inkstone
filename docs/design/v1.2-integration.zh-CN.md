# Inkstone 1.2 集成方案

以 v1.0.0-rc.4 为基线。RC.5 的问答质量、1.1 的可执行任务和 1.2 的语言与上下文体验共用一个测试候选。用户可以从一段讨论中挑出承诺，写回笔记，在任务与日历中跟进，并查看生成答案和同伴反馈各自用了什么信息。

## 分阶段实施

| 阶段 | 交付位置 | 判定依据 |
| --- | --- | --- |
| RC.5 问答 | 检索、候选准入、追问和引用校验 | 沿用冻结语料、评分规则和 RC.4 对照结果。分别记录离线命中、真实模型回答与人工评分 |
| 1.1 任务 | Markdown、任务与日历、对话 | 普通勾选项、代码示例与受跟踪任务可区分。完成、截止、等待跟进与执行时段各有单独的语义。从对话保存前显示原话和目标文档 |
| 1.2 集成 | 中英文界面、回答的上下文、页边同伴 | 切换语言后文档和证据字面内容保持一致。能核对问答模型的请求和同伴本地事件的来源；缺失观测时显示未知 |
| 候选验收 | 同一源码树、桌面候选 | 执行前端与 Rust 回归、构建 CLI 与 macOS App，核查隔离资料下的关键操作。记录仍需真实用户或真实服务确认的指标 |

## 写入与兼容约定

Markdown 是任务的权威来源；文档 ID 与任务 ID 共同定位，日期使用机器可读格式。现有日历日程和普通检查项可以继续独立使用。对话的行动项需要用户选择和确认，按目标文档当前修订一次写入；重复点击、文档切换、外部修改和未保存编辑均需覆盖。会话原文、私有来源与模型凭据不会随任务元数据导出。

回答的资料候选、实际请求和最终引用分别取证。请求记录只保存用途、结果和计数，历史记录缺字段可继续读取；同伴的回顾沿用已确认手札和可撤回设置。界面语言跟随系统或用户选择，用户文档、历史原文及日期存储独立于显示语言。

## 交付判定

首个集成制品标记为 1.2.0-beta.1。每个功能通过真实入口或对应集成测试验证，按“已验／待验”记录。正式版继续沿用既定的问答质量目标，另行安排用户试用与发行。参阅[问答质量计划](after-rc4.zh-CN.md)、[任务设计](v1.1-tasks.zh-CN.md)、[语言设计](localization.zh-CN.md)和[对话与同伴上下文](context-and-companion.zh-CN.md)。
