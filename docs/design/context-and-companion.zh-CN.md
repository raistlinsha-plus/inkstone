# 对话用了什么，同伴记得什么

2026-11-22 设计提案，基于 v1.0.0-rc.4。用户常遇到两个不同的问题：「笔记明明写了时间，这轮为什么没答出来？」以及「桌宠怎么知道我做完了这件事？」两处都应有一个能点开的答案，但可读取的材料和能执行的动作各有边界。

## 参考与起点

DeepSeek Harness 插件 dsh-context 可以查看某次请求携带了哪些类别的内容、与上次相比增加或减少了什么，以及压缩或剪枝等事件。它也区分估算与实际观测。Inkstone 借鉴这三个交互，使用自己的 Rust 请求与本地同伴事件作为数据来源。首期无需引入插件运行时、跨会话仪表盘或新的后台模型。[上游项目与固定版本说明](https://github.com/bowenliang123/dsh-context/blob/9de41ff3e427405d6abaa91a508feb561554f71c/README.md)

Inkstone 已有活动分支、回答偏好、本轮记忆和来源线索。现有显式历史背景最多预览 400 字，附加的偏好与背景共用最多 800 字符预算，整次请求另有模型配置预算。页边角色会根据工作状态切换反馈；开启回顾后可展示当前空间、当前角色最近的有效经历。下一步把已有信息放到用户做决定的地方，并标清哪些是在本机发生的。[现有问答详情](../../src/assistant/ConversationPanel.tsx) · [可控记忆交付记录](../DELIVERY-v0.7.1.md) · [页边角色](../../src/companion/CompanionPet.tsx)

## 两个入口

| 入口 | 默认可见 | 点开后可操作 |
| --- | --- | --- |
| 回答下方「本轮上下文」 | 一行摘要，例如「当前笔记 · 使用 2 段原文 · 沿用上轮问题」。纯改写、离线检索和模型失败使用各自的实际状态 | 查看各阶段的资料范围、历史和偏好；对选入的材料看来源与行号，对实际引用看对应断言。可点「下轮移除这份附件」「本轮重问时忽略旧背景」或回原文。重问产生新回答候选，旧回答保留原有记录 |
| 点击同伴，在回顾卡选择「为什么提起这件事？」 | 例如「你在这个空间确认过一条经历」。只在回顾或用户主动打开时显示。日常写作沿用安静、减少动态等设置 | 查看当时确认的手札；隐藏这次回顾、关闭同类回顾或到手札编辑／删除。删除经历沿用现有成长记录规则，向用户说明影响 |

**举例。** 周一的对话里讨论了两种发布日期。周三用户切到另一篇笔记问「那周五呢？」。问答页可显示「本轮换了文档；未沿用上轮的日期；当前笔记只找到会议日期」，用户可以补选背景或澄清。之后用户在《发布复盘》里完成了“更新手册”，主动确认记为同伴经历。同伴才可以回顾这项成果。单纯聊过计划、模型建议做或日历已经到期，都不足以生成“你已经完成”的经历。示例文案随应用语言显示，出处按原文打开。

若用户只想知道模型用了多少上下文，可在回答摘要展开「用量」；也可从同伴菜单打开当前回答的同一面板。这个按钮只负责导航。桌宠动作优先表达「工作中」「需要你确认」「已完成」；安静模式只保留用户可主动查看的入口。这样不会因频繁提示余量打断写作，也不会给角色新增读取资料的权限。

比如同一时刻，回答详情可以显示「问答模型收到 2 段原文 · 回答引用 1 段」，页边同伴的详情可以显示「这次动作来自回答就绪事件 · 本机处理 · 模型请求 0 次」。开启经历回顾时，第二条可换成「来自你确认的手札 · 查看来源」。这使用户能分别核对聊天的模型消耗与同伴自身的上下文来源。

## 记录到请求，解释到回答

1. **发送前。** 在编排层按目标提供方和用途组装有类型的条目：当前问题、相关历史、显式偏好、文档摘录、已发布且有效的 Wiki 摘录、附件、网页摘录。优先保留当前问题、用户限定的范围和能支撑答案的原句；对过长历史按活动分支优先保留最近相关轮。源文档不能容纳时标记本轮实际省略的依据。用户主动选择的来源若未纳入，应有原因和补救入口。输入框能预览的是计划范围，发出后才显示实际情况。
2. **发送时。** 一轮可能发起多次不同服务调用。将查询向量化、重排、网页查询、可选原文核对、最终问答、聊天提取行动项分别记录。只有实际交给传输层的请求才记「已尝试发送」，区分拿到响应、发送前取消和发送后结果未知。某段只用于本机筛选、只送给重排服务、进入最终问答请求或最后被回答引用，四者可分别验证。面板只解释应用掌握的输入与引用情况。
3. **用量。** 保留现有字符预算语义。提供方返回 usage 时单列其报告的输入、输出和适用的缓存数据；未返回时显示本机统计的字符数，若采用指定模型的分词器估算，则写明模型和「估算」。上下文窗口大小未知即不显示百分比。最新一次请求的输入占用、整轮各请求的累计消耗分别展示。重试和切换模型需单列，不能用字符数推算账单。
4. **轮间变化。** 在同一会话、同一活动分支比较兼容阶段的条目，显示「新增附件」「文档版本已变」「按预算省略较早背景」等原因。旧版会话没有该记录时显示「此版本未记录」。首期只披露实际截断或省略；后续若引入历史摘要，应保留所覆盖轮次、生成时的范围和失效规则，另行评测对追问的影响。

**建议的数据契约。** 对每个回答候选关联版本化的请求记录，保留请求用途、轮次／分支／候选、尝试序号、结果、来源类型、受管来源引用与版本、纳入或省略原因、计量单位和计量依据。分组差异以稳定引用比较；历史问答及用户内容仍从既有存储读取。只保存必要的本地元数据。省略项若涉及未授权空间，只计策略结果，不登记标题或可逆路径。用户能从快照重访的范围受当下访问权约束。[请求适配层](../../src-tauri/src/providers.rs) · [会话编排](../../src-tauri/src/assistant_runtime.rs) · [问答偏好与背景](../../src-tauri/src/assistant_memory.rs)

**同伴专用输入。** 沿用当前角色与空间、安静／动效开关、会话工作状态、已确认且仍有效的经历。建议为每次回顾传一个本地原因码和可检查的经历 ID。任务版仅在用户主动开启并确认该事件的语义后扩展，例如「这次完成，记入手札」。打开角色时按需解析；角色切换、撤回、文档移入回收站和删除卡片后重新判断。桌宠的状态动画和回顾都可以在没有模型凭据时运行。角色记忆、问答事实依据和评测轨迹分别持有；任何从同伴进入问答的内容都应由用户显式选择并在发送前可见。[同伴存储与验证](../../src-tauri/src/companion/mod.rs)

## 何时交付

| 阶段 | 交付范围 | 怎么验 |
| --- | --- | --- |
| RC.5 | 用合成夹具在问答诊断中区分候选、准入、最终请求和有效引用；验证字符计数与各服务调用。保持现有正式版质量目标 | 同一问题用本机检索、仅聊天服务、启用重排三种配置对照，记录应与模拟服务收到的材料一致。取消、重试和权限撤回各测一次；无请求的场景显示本机处理 |
| 1.1 测试周期 | 问答的一行入口及展开详情；同伴回顾的本地来源说明与关闭入口；行动项预览明确“来自哪轮、哪句、谁说的”。优先提供简中／英文文案 | 复现一次有据、一项缺证、一次换文档、一次没有 usage 的模型响应。两名角色、两个空间、同一任务重复点击都有对照。任务删除、会话分支切换及缩窄窗口后不串用上下文 |
| 1.2 及以后 | 根据试用反馈补轮间变化、跨语言引用说明、实际可得的用量趋势。仅在历史丢失确实造成问题时评估可回溯摘要 | 试用者能从一轮失败回答指出缺了哪项材料，也能说出同伴记住什么、怎样撤回。若这两项仍说不清，优先修入口与文案 |

**通过线。** 合成服务逐请求核对发出项、被取消项与面板记录；撤权后界面新披露的私有内容、跨空间串用、仅打开同伴产生的模型调用，均为 0。历史清理时联动清理私有引用，保留“来源已不可用”的说明。交付说明列出实际覆盖的服务和语言。中文、英文、emoji 与混排用相同语义分别测量，语言切换不更改历史引用、时间戳或成长状态。[多语言方案](localization.zh-CN.md)
