# Inkstone 1.0 产品与发布方案

评审稿 · 2026-11-21 · 基线为已公开的 v0.9.6。建议下一公开候选命名为 v1.0.0-rc.1，承接原路线图中 v0.10.0-rc.1 的评测和兼容工作。下文的目标值和版本安排均为提案。

RC.2 回归后的问答修复与正式版验收安排见第 8 节。

## 1. 用户拿到什么

**Inkstone 是一间本地 Markdown 书房。你可以在自己的资料里用中文提问，点开出处核对，把答案写回笔记；值得长期维护的知识由 Wiki 持续整理。**

第一批用户是已经在 Mac 上积累项目资料的人。他们往往同时有计划、会议记录和复盘，需要搞清楚“当时怎么定的、后来做到了哪一步”。读写、搜索、模型问答和 Wiki 共用同一组可带走的文档。墨团、砚舟和知微给书房留下辨识度，用户可以自己决定何时让它们出现。

**建议首发形态为 Apple Silicon Mac 的 1.0 稳定源码版**，沿用 macOS 13+ 的项目目标、中文与英文说明及自带模型 API 的方式。面向能从源码运行的用户，首页给出构建入口和免安装的模拟演示。面向希望下载即用的用户，待同一分发文件完成签名、公证、许可复核和干净 Mac 验收后，再增加安装包入口。首次获取、运行和升级分别提供说明。[现行产品说明](../PRODUCT.md) · [发行流程](../MACOS_RELEASE.md)

## 3. 用一件真实任务设计主流程

发布演示和用户测试都可以从仓库的两份虚构资料开始。第一次试用时，用户只需看懂自己在哪个空间、可以导入什么、下一步怎样核对。[阅读活动计划与复盘](../../examples/v0.7.3/README.md)

1. **收进来。** 在空间首页选择两份笔记，导入结果给出可以立即打开的空间副本。有同名或重复材料时能打开已有副本；部分失败时回到失败项。无密钥用户可先用有标识的离线练习体验“查到并打开原文”。
2. **问清楚。** 选这两篇笔记，问“本来打算办几场？到现在做了几场，大家觉得怎么样？”理想首屏读作“计划 **4 场**〔计划〕，已完成 **2 场**〔复盘〕。复盘写明尚无满意度调查结果〔复盘〕。”每个引用打开对应原句。追问“还差几场？”可给出 **2 场**，标明由前两项相减，并沿用资料范围。换成“帮我润色这句通知”时，独立问答可以直接改写。
3. **接着写。** 从编辑器发问时，打开引用后能一键回到发问前的文档、滚动位置与选区。保存回答得到可编辑的 Markdown，并保留当轮出处。模型连接中断保留问题草稿；恢复后由用户重试。默认先展示回答和关键出处，检索策略、耗时、降级原因仍可展开查阅。
4. **下次还能用。** 选定这两篇资料建立一个 Wiki 主题。把复盘从“完成 2 场”改为“完成 3 场”时，审阅页先展示受影响结论、旧值、新值及对应原句。发布后新问题引用现行资料。旧回答仍能表明自己的版本；撤权前预览影响；确认清除后，受影响的 Wiki 页面、历史和待审改动一并清除，原始笔记保留，后续问答重新检查授权。
5. **写完留个纪念。** 用户保存后可从页边同伴预览并确认一条经历，也可直接收起角色。专注、减少动态与窄窗书签沿用已有行为。故事和 CG 在「书房同伴」中阅读，问答正文始终留给用户的问题。

### 日常操作：临时菜单如何收起（P0）

在 v0.9.6 的文档列表组件中，用一篇示例笔记复现了这个场景：打开行尾「…」，再点击同侧栏的「查找文档」输入框。输入框已经获得焦点，「重命名标题」仍留在屏幕上。该组件按整个列表判断焦点是否移出；点击文档行另有关闭逻辑，因此看起来时好时坏。编辑器「插入」已经按菜单自身的边界识别外部点击，可用作对照。

| 用户动作 | 1.0 期望 |
| --- | --- |
| 点击图标展开，随后把指针移向某个选项 | 菜单保持展开，经过图标和菜单之间的空隙也能继续选择。 |
| 点击正文、搜索框或问答输入框 | 菜单当次收起，同一次点击在正文落下光标或让输入框获得焦点，可以立即打字。点击普通空白也能收起。 |
| 从一个「…」直接点到另一个「…」或「插入」 | 一次点击完成切换，只显示刚打开的菜单。点选普通命令后收起；命令若打开重命名框，焦点进入新表单。 |
| 用键盘打开、取消或离开 | Enter 或空格可以打开。命令菜单支持方向键选择。Esc 只关闭最上层并把焦点交还触发按钮，Tab 离开菜单时顺着页面向前走。鼠标点到别处时焦点留给所点击的目标。输入法正在选字时，优先交给输入法处理。 |

此规则用于临时动作菜单。「资料与检索设置」等页内展开区保留用户选定的展开状态。重命名、编辑链接等含草稿的表单有明确的提交和取消动作，点击外部不能静默丢失输入。子菜单和浮出的选择器属于当前操作的一部分。

**RC.1 验收。** 在同一候选包覆盖侧栏与空间首页的文档「…」、编辑器「插入」与标题下拉、问答「更多会话操作」。用合成文档检验外点、连续切换、Esc、Tab 和中文输入。至少在 macOS 原生窗口用鼠标或触控板完成「展开 → 点正文 → 直接输入」与「展开 → 点搜索框 → 直接输入」，核对实际光标位置和输入结果。窄窗下复查菜单边界，键盘和 VoiceOver 复查打开状态及焦点去向。留下需额外点击、误触另一命令或丢失草稿的入口名称和复现路径；高频路径的同类问题修复后再放行。

### 在其他 AI 工具中引用本地资料（P1，可选源码预览）

有些用户已经在终端助手中写周报或修改方案。只要给它一份活动计划和一份复盘的出处，它就能接着手头的任务写下去。Inkstone 提供已整理资料的检索和原文定位，调用方负责组织回答。这样能省去重复导出、手工挑选片段和维护第二份索引。v0.9.6 的可执行入口启动桌面应用；下面的命令名、协议和界面均为提案。

**用户路径。** 在 Inkstone 的「设置 → 外部工具」创建本机连接，明确选择允许读取的受管理空间，查看将返回的内容范围；连接使用独立可撤销的凭据。终端侧完成一次配对后可在桌面应用关闭时查询现有索引。日常仅需“查”和“核对”两步，示意如下。空间标识由授权页提供，引文标识由上一步结果提供。

```sh
inkstone-cli search --space "$SPACE_ID" --query "阅读活动原定几场，实际完成几场？" --json
inkstone-cli read --space "$SPACE_ID" --ref "$REF_ID" --json
```

| 操作 | 第一版的约定 |
| --- | --- |
| 查资料 | 在一个已授权空间内用本地 BM25 查询已建索引的受管理文档。返回有数量和长度上限的片段、标题、版本、行号、引文标识、是否具备直接证据以及实际检索模式。调用方可区分空结果、只有线索、索引未就绪和暂时忙。 |
| 核对原文 | 重新核对连接授权、文档状态和内容版本，按引文取回有限原文。引文绑定空间 ID、文档 ID、版本和行区间，重新建索引后仍可校验同一版本。原文更新后返回“引用已过期”，调用方重新搜索。 |
| 管理访问 | 默认零授权，每次调用检查实际授予的空间。撤销只影响后续经 Inkstone 的读取。已有 shell 或文件权限由操作系统管理，已交给外部工具的片段由该工具处理。授权时说明外部工具可能把片段发送给它自己的模型。 |

**实现。** 从现有 Rust 检索流程抽出无写入的文档查询与引文解析，桌面和 CLI 共用这一段。命令行使用显式空间和独立只读连接，输出带协议版本的 JSON，将诊断写到标准错误。公开输出仅包含上述证据字段。现有桌面搜索会刷新索引标题，数据库打开路径可执行迁移，桌面请求之间还会相互取消。索引需要修复或升级时由桌面端处理；外部查询使用自己的取消状态。预览保持离线，不使用嵌入、重排、聊天或网页服务的钥匙串凭据。[桌面检索](../../src-tauri/src/lib.rs) · [索引打开与迁移](../../src-tauri/src/db.rs) · [现有结果结构](../../src-tauri/src/models.rs)

**交付判定。** RC 阶段用两个含同名文档的合成空间，跑通一个真实外部工具的“查 → 读 → 引用”。在相同资料、原文 BM25、相同预算下比对桌面和 CLI 的片段、版本与行号。测试撤销、回收站、改稿、索引未建、桌面关闭与桌面并发保存。跨空间返回、撤权后读取、过期引文误配新原文、外部模型请求、资料和索引的非预期改写均须为零。单列 CLI 检查，沿用已有 40 题检索和真实问答评测口径。通过后可随 1.0 发布源码预览，未通过则移至 1.0.x，继续按核心写作、问答与 Wiki 的门槛判断正式版。

**后续。** 先观察用户能否在自己的工具里完成一次有出处的任务。若目标客户端支持本机 MCP，可在 1.1 复用相同的授权与两项操作，通过标准输入输出接入，无需监听网络端口。已有桌面 Wiki 编纂授权与第三方读取授权分别管理；公开已发布 Wiki、可选向量和远程重排时，分别交代可读来源和传输给服务的数据。根据实际请求再排期导入、写回或自动索引。[MCP 本地传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

## 5. 1.0 的稳定性承诺

- **文档与备份。** 以 v0.9.6 的普通 Markdown、已支持的内容块、空间与文档 ID 为兼容基线。用含附件、回收站、历史、问答快照、Wiki 和同伴进度的旧库测试升级。用含 Wiki 的格式 3 和无 Wiki 的格式 2 备份分别在新目录验证恢复；对任何需要迁移的数据先留可校验的备份。回退前另存 1.0 中新写的内容，演练取回它，再回到升级前的资料状态。索引可重建，跨机使用时单独配置钥匙串凭据。1.x 若调整持久化格式，随版给出迁移、失败恢复和历史链接测试。
- **范围与隐私。** 离线编辑与关键词检索可独立使用。引入聊天、嵌入、重排、Wiki 编纂或公开网页时，界面要能说明哪类数据会交给哪个已配置服务。撤权或模型故障时不扩大所选范围；降级要显示实际执行方式。问答背景与同伴经历分别管理，经历需要用户预览确认。
- **技术边界。** 复用当前 Tauri、React、Rust、SQLite 和文件存储。在提问、召回、重排、装配、生成五处保留可对照的评测记录，只在测试夹具中保存合成原文。先用漏证样例定位问题再修改对应模块；若关键词模式就能解决，保留这条低成本路径。[技术栈](../TECH-STACK.md)

## 6. 发布如何判定

下列数值是建议的候选准入或正式发布目标。本次为设计评审，运行结果需由候选提交产生。

| 检查 | 方法与判定 |
| --- | --- |
| 中文证据进入模型上下文 | 冻结 40 题中 34 道有据或部分有据的题，至少 24 道取齐；保住旧集 9/9；40 题越界为 0。64 题开发集另跑并报告回退。逐题记录是召回遗漏、排序丢失还是装配截断。 |
| 真实答案与引用 | 冻结同一模型与资料，对照关键词、混合、混合加重排。正式判断另用独立准备、开发阶段未见的资料与问题，事先冻结评分规则，建议至少 40 题。由人工逐题核对，关键问答正确率 ≥90%，所有需出处的关键断言中，有可打开且支持该断言的引用者 ≥95%，严重错误为 0。正确处理部分缺证、拒答及冲突可得分；超时、服务失败、漏引保留在相应分母并单列。另测自动联网、明确禁止联网和通用改写。公布模型、样本量及计数。[评分规则](../../evals/v0.9.1/RUBRIC.md) |
| Wiki 生命周期 | 用真实模型在合成资料上完成初建、改值、审阅或仅发摘录、撤权、重开再问。分别审查提案与正式页；无依据的比较被发布为事实为 0，撤权或失效证据进入新回答为 0。 |
| 首次使用、写作与无障碍 | 观察 5 位目标用户。目标为至少 4 人在 2 分钟内从离线示例打开原文，模型已就绪时至少 4 人在 5 分钟内从自有资料完成问答、核对与保存。安装及模型配置另计时，分列配置失败和放弃人数。另在原生窗口验证 960×640、两种外观、系统中文输入法、键盘及 VoiceOver 的关键路径。记录 7 日回访及至少 5 个自然日的同伴体验，作为下一阶段输入。 |
| 数据与性能 | 在隔离的 v0.9.6 数据副本完成升级、重开、恢复和回退；原件、受管理正文及附件逐项校验，确认 ID、引用和进度可用。固定机器与资料，比对冷启动、4 万字编辑和多轮问答的首段可读时间，分别列出本地耗时与模型等待。基线和可接受退化幅度在优化前锁定。 |
| 源码发行 | 从锁定提交在干净检出目录构建，跑全量离线回归及上述独立验收。手册、演示、默认分支与标签一致，发布源码、SHA-256 和已知限制，再匿名下载复核。公开应用包另需真实 Developer ID 签名、公证、Gatekeeper、二进制许可与干净 Mac 验收。 |

**放行规则。** 数据丢失、范围越界、撤权后仍发送资料、无依据结论以已验证事实发布，任一项可复现即停止正式发布。问答质量或关键写作流程未达标时保留 RC，只修落榜场景并补跑受影响测试。5 人观察提供易用性线索，7 日回访和同伴喜好不用于推断总体留存。

## 8. RC.2 复盘与 RC.3 问答修复提案

2026-11-21。建议在正式版前增加 v1.0.0-rc.3，集中解决一个用户问题：自己的笔记里明明写了答案，换种问法却只收到“证据不足”。

### 诊断与第一个实验

独立 52 题的真实关键词运行来自 RC.2 开发构建：49 题在本机返回缺证，1 题要求澄清，2 题进入聊天模型。独立 AI 对照封存答案严格判对 1/52，人工盲审待做。最终代码离线回放时，实际搜索的 51 题都有候选，2 题通过证据筛选，2 题进入生成上下文。另一组已知 40 题中，最终关键词取齐 27/34 道有据题；开发构建的真实混合与重排在同组也各取齐 27/34。不同题集、构建、取证分数与作答分数应分别报告。[RC.2 验收](../DELIVERY-v1.0.0-rc.2.md)

在当前实现中，普通关键词证据判断会看分词覆盖，日期、对象、单位等另有条件。重排只能保留或剔除之前已获准的证据；一个高分候选不会因此升级成证据。资料问答在本地证据为空时会直接返回，聊天模型没有机会读这些候选。因此要分别测候选质量与筛选质量。

先另外准备一批开发资料，包含可以回答、部分可答、原文互相矛盾、只有相似内容以及指代不清五种情况。独立标注者先在完整的获准资料中逐个小问标出能作答的原句与版本，然后对照同一候选提交的前 8 段，分清三种漏答：

| 观察 | 决定改哪里 |
| --- | --- |
| 原文有答案，前 8 段没有 | 检查分块边界、中文改述、追问对象与候选的文档分布，再比较 BM25、混合、重排。 |
| 候选里有能回答的原句，现有规则拒绝了它 | 优先做下面的按需选句，单测实体、条件、单位、时效和否定。 |
| 直接把人工标出的原句交给同一生成器，答案仍不对 | 查回答生成、组合推算和引用绑定。即使检索改好，这一部分也要单独修。 |

使用同一批问题比较现状、加入选句、直接给已标原句三种运行，固定资料范围、模型、提示词版本和上下文预算。此前 52 题及封存答案留给独立评审；开发举例和阈值调整使用新开发集。

### 回答如何产生

1. **确定本轮对象。** 将复合问题拆成可各自核对的小问，保留时态、数量单位和适用条件。追问沿用上轮所指对象与已引用来源，再校验当前授权、版本与分支。上轮未形成答案时，根据用户问题和当前笔记重新取证；只有不同指代会改变答案时才追问用户。
2. **保留已有快速路径。** 原规则已经为每个小问找到直接依据时照常生成。其余小问从已授权范围内最多取 8 段，按小问和文档去重。有精确短文可直接在该文档定位，表格保留表头、单位及完整行。已选严格重排、撤权和版本检查继续生效。
3. **在候选里选原句。** 应用先给完整句或表格行编号，让阅读模型在一次批量请求中为各小问选择句子编号，或返回“缺证”。需要模型辅助拆问时，在这一次请求中同时完成。模型只可选择应用提供的标识。原文、路径、引文行号和可点击链接由应用重读当前文档后生成。位置匹配仅能确认文字存在；还需检查所指对象、条件、数值或否定确实支持回答。对复杂关系把握不足时可展示原句供核对。
4. **允许只答一半。** 各小问分别呈现答案和紧邻依据。两份版本冲突时并列原文与日期。缺项只说明本轮找到了什么、哪项仍待核实。若做差值或合计，列出每个输入、单位和来源，能由程序复算时再给出数值。索引未完成、模型失败、授权撤回与查不到依据要分别提示，让读者能采取不同操作。
5. **限定新增耗时与传输。** RC.3 的试验预算为每题最多一次额外选句请求、8 段、合计最多 4,000 个原文字符，实际按服务剩余上下文收缩。可先在本机做精确选句。本机模型可用时支持就地阅读，远程问答服务要在设置中写明“候选原文片段也会送去核对”，按已确认的传输范围使用，旧设置保留既有边界。读取前、发出前和返回后核对空间、资料归属及版本；中途取消或切换空间即丢弃本轮结果。离线本地检索和只读 CLI 沿用现有契约。

52 题覆盖文档空间问答链路。通用问答显式选文件或临时附件时，现有实现直接使用短文，长文则选取片段，走另一条路径。该入口的事实问答要单测；翻译和改写继续直接使用用户选定的文字。“本轮不搜索网页”与“模型调用全程在本机运行”应分开验证。

代码接入点是现有证据标记、生成上下文和问答路由。先从「问这篇文档」到「空间问答」接入，再覆盖通用问答里的显式选文和会话附件。两条入口使用各自的权限、所有权和来源版本校验，共享选句与逐项回答逻辑。Wiki 命中仍回到获准原文。后端日志记录分阶段数量、耗时、降级原因和调用次数；日常日志使用匿名统计。 [证据标记](../../src-tauri/src/evidence.rs) · [检索与重排](../../src-tauri/src/retrieval.rs) · [资料问答](../../src-tauri/src/lib.rs) · [显式选文与附件](../../src-tauri/src/assistant_runtime.rs)

### 用户会看到什么

例如，虚构的《周末借阅安排》写着“六一当天少儿室延长至 18:00”，另一份《活动通知》只写“讲座安排另行通知”。用户问“少儿室几点关，讲座几点开始？”时，回答可以直接写：“少儿室当天 18:00 关闭〔借阅安排，第 4 行〕。讲座的开始时间仍待通知〔活动通知，第 2 行〕。” 用户点击任一出处即可看原句。若通知只谈借阅、没有提讲座，第二句改为“本次片段不足以核实讲座开始时间”。两种情况下，第一句都能保留。

### 落地顺序与验收

| 阶段 | 交付与决定 |
| --- | --- |
| 定位损失 | 交付逐小问的开发集标注、前 8 段完整入证率、误拒与误答分类，以及直接提供正确原句时的回答结果。先处理贡献最大的一类。 |
| RC.3 候选 | 接通按需选句、部分回答和来源跳转；在同一构建对照三种检索模式。分别报告有答案题的错误拒答率、无答案题的误答率、引用支持率、按题额外请求数、P50/P95 延迟。试行目标为“前 8 段已有直接证据”的小问中，至少 75% 给出正确且有据的回答；无答案和相似干扰用例同时逐项核对。 |
| 正式版决定 | 使用新封存、开发阶段未见的资料，由人工逐题评分。沿用既定门槛：关键问答正确率 ≥90%，关键断言引用支持率 ≥95%，严重错误 0。公布分子和分母，服务失败和误拒纳入统计。新增、撤回、跨空间、引用后原文改稿、附件被移除、取消和禁网的回归均需通过。旧 40 题保住 27/34 完整取证、旧 12 题 9/9、64 题开发集 49/52，并核对各题组的越界记录。沿用第 6 节的桌面、首次使用与分发验收。 |

第一轮可先在离线合成资料上完成定位、选句契约和交互测试。冻结候选代码后集中跑一次真实模型对照，留存同一构建的报告和盲评分表，减少重复等待钥匙串授权。
