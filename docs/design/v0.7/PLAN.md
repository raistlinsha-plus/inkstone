# Inkstone 后续改进与 v0.7 开发计划

2026-11-04。v0.6.6源码首发已完成；后续以持续维护公开主线、小工作包和可核对验收为原则。v0.7同时提升问答主路径与角色陪伴，分开模块和候选版本，避免每轮都重做全产品。

## 1 优先级

| 优先级 | 问题 | 本轮处理 |
| --- | --- | --- |
| P0 | 文档保存、来源身份、范围和数据安全 | 每包保持回归；任何退化先停止新增功能 |
| P0 | 问答像一次性结果，缺少完整会话阅读路径 | 会话/范围/追问/来源/落地先行，做展开问答工作区 |
| P0 | 角色成长写入、去重、关闭与删除容易相互污染 | 独立库、成功凭据、事务、代际和备份先于真实资料试用 |
| P1 | 长标签、工具栏、间距、键盘和窄窗体验 | 用当前任务路径补原生IME、VoiceOver和三档布局，按域修复 |
| P1 | RAG抽象改写仍保守漏答 | 冻结新小集与预算，定位门控/条件，不降低全局阈值追分 |
| P1 | 像素水墨角色与内容吸引力 | 墨团样片先签收，三角色基准后扩成阶段资产 |
| P2 | 系统桌宠与长期成长 | v0.7.1评估浮层，v0.8再开默契/共著 |

## 2 版本顺序

| 里程碑 | 范围 | 退出条件 |
| --- | --- | --- |
| v0.6.6后维护 | 处理首发构建/启动/数据阻断；IME/读屏专项；CI失败诊断 | 不捆新角色、格式或大检索重构；实测与未跑项分列 |
| v0.7.0-preview.0 问答底座 | 会话模型、展开问答、范围冻结、来源预览、停止/重试、回答落地 | 隔离合成资料三轮问答可用，跨空间/晚响应与保存保护通过 |
| v0.7.0-preview.1 墨团闭环 | 独立角色库、墨团初遇/相识、确认经历、故事/相册、收起关闭 | 一条垂直链路；重复/失败/重启正确；不接真实私人经历 |
| v0.7.0-preview.2 三角色候选 | 三角色前三阶段、九章、同行选择、偏好、删除/导出/完整备份；问答P1 | 数据控制及迁移/恢复通过，才开放真实资料持续使用 |
| v0.7.0-rc | 最终9立绘/6CG、动作小样、原生检查、小范围自然使用 | 至少5个不同使用日观察；人数与反馈如实记录；关键阻断为0 |
| v0.7.0 | 体验收口、文档、更新与源码Release | 正式素材/许可签收，冻结CI、回归、制品与公开下载一致 |
| v0.7.1 | 真实反馈修订；评估应用外浮层 | 先解决打扰、误挡、性能与接续任务，再决定浮层价值 |
| v0.8 | 默契/共著、后续剧情/纪念物 | 基于实际价值调整门槛，保留存档兼容 |

相比旧计划的变化：首条角色切片从砚舟换为墨团；在它之前加入问答preview.0；正式三角色范围保留。已有九章原型复用，程序示意图换为像素水墨概念；不重新开一轮全产品原型工程。

## 3 工作包与依赖

| 包 | 唯一主要成果 | 依赖与检查 |
| --- | --- | --- |
| A1 | 会话/轮次/来源快照契约 | 从当前ask状态提取；先保持现有单轮行为回归 |
| A2 | 会话时间线、Composer、展开阅读、来源抽屉 | A1；合成三轮、键盘、范围切换 |
| A3 | 取消/流事件/候选、保存插入、历史数据控制 | A1/A2；晚响应、内容校验、冲突与重开 |
| B1 | 同伴schema1、成功receipt、幂等与代际 | 与A模块分离；先跑失败/关闭/reset竞争 |
| B2 | 墨团初遇/相识闭环 | B1；主动确认、安静标记、旧形象、关闭 |
| C1 | 三角色九章/选择/资源manifest | B2；稳定ID、汇合和缺资源 |
| C2 | 偏好/删除/导出/备份迁移 | A3/B1/C1；两个新库及待处理不遗漏 |
| D1 | 最终美术与原生/自然使用 | 各候选冻结后集中验收，实际失败归对应域 |

每包以可审阅提交结束：契约→局部检查→集成→更新实际状态。搬代码与改行为分开；检查图按修改域选用。角色/会话schema、锁文件、共享渲染和存储变化扩大回归；只有美术/文案变化不重复付费RAG评测。

工作包容量建议以半天以内的可见成果为拆分起点，超出就先缩范围；这不是完整版本的时间承诺。没有足够可比样本，不再声称总体提速25%–40%。累计记录实现、返工、自动、构建、原生和外部等待。

## 4 RAG专项改进

沿用BM25＋向量＋RRF＋可选重排。v0.6.6新集合覆盖32/32、旧勘误集合19/24说明命名比较有改善、抽象改写仍有缺口，不是100%答案准确率。先处理问答体验，再独立评估抽象指代与分散条件，不在角色包里顺手换检索器。

新增一组不重复旧模板的多轮/指代/条件分散/表格缺测题，先冻结支持关系、hash、拒答条件和预算；开发回归与未见检查分开。至少安排一次非实现者审阅，没有则明确同作者。付费模型使用显式累计预算与停止条件，默认测试不读Keychain；现有服务配置不新增角色专用key。

用户主路径显示“依据不足/来源更新/索引失败”等可行动原因，高级诊断保留证据门控，不让重排高分或旧聊天文字成为证据。对外分开报告Recall、证据覆盖、最终事实审阅、拒答与首token/总时延。

## 5 原生与发行

主开发以隔离数据、无系统凭据桩和本机协议样例进行；只在冻结候选集中做生产冷启动、真实API与Keychain验证。锁屏时继续构建/自动测试，不存系统密码、不降低锁屏保护。稳定签名/公证仍需发行专项，不能承诺每次更新都不再触发系统授权。

源码版本与稳定安装包分开判定。安装包发布前补余下20项许可文本/二进制分发复核、依赖适用风险、Developer ID/公证、干净机器安装/升级/恢复及最低系统兼容。角色资产的来源和许可独立于Apache代码登记，概念图不直接算正式成品。

## 6 立即下一步

先评审原型的“展开问答→比较→来源→追问不足→保存文档”和“墨团→确认完成→新章→相册→收起/关闭”两条链路。范围通过后先实施A1/A2问答preview.0，再实施墨团B1/B2；三角色正式美术在基准样片签收后扩量。
