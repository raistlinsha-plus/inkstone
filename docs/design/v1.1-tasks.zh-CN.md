# Inkstone 1.1 设计提案 · 从对话到待办，从日历回到笔记

**交付状态**　v1.2.0-beta.1 构建 10203 已支持独立的任务和日历入口、Markdown 富任务行、周历排期与拖动改期。下文保留早期设计与扩展设想。已实现的操作和验收见[中文手册](../USER-MANUAL.zh-CN.md)与[交付记录](../DELIVERY-v1.2.0-beta.1.md)。

**用户故事**　周一复盘时，作者答应周五前交手册，还需要问维护者一个签名问题。他从聊天中选两条行动，保存进《发布复盘》，给写手册安排周三下午，给求助安排周四跟进。周三从日历打开这件事，回到复盘中的原句。正文勾选后，清单与日历同时显示完成。

## 入口和用语

这些入口以简中／英文一起试用。任务 ID、来源定位、勾选状态与存储日期在切换界面语言时保持一致。批量提取面板可查看本次实际采用的聊天片段；任务完成后由用户确认是否记成同伴经历。详见[多语言设计](localization.zh-CN.md)及[上下文使用说明](context-and-companion.zh-CN.md)。

| 在哪里 | 用户能做什么 | 写入位置 |
| --- | --- | --- |
| Markdown 正文 | 在插入菜单或斜杠菜单选「任务」，键入标题。普通勾选项可通过行菜单「跟踪为任务」加入空间清单，已有标题和勾选状态直接沿用。 | 光标所在处或选中的原清单项 |
| 左侧「任务」 | 打开今天、待安排、等回复、已完成或来自问答的清单，快速新建并选择所属笔记。 | 指定的 Markdown，或空间的默认任务笔记 |
| 左侧「日历」 | 直接打开周历，查看全天截止、跟进和执行时段，拖动执行时段改期。可切换月历或日程清单。 | 原任务或日程所在的笔记 |
| 对话或回答 | 选一段文字点「转为任务」；完整回合可以点「提取行动项」，逐条修改标题、日期与归属，勾选后一次添加。已添加的显示「查看任务」。 | 必须显示目标 Markdown。文档问答默认当前文档，空间问答记住本次目标，通用问答先选空间和文档。 |
| 求助与等待 | 可以从任务打开「请 AI 帮我拆解」，在新问题草稿中带入用户选中的文字。要找人协助时，可在正文写对方与要问的问题，标为「等回复」，指定跟进日期。 | 求助内容保存在笔记；发送给模型沿用问答的发送操作。对外联系由用户完成。 |

窄窗和键盘流程使用现有菜单及弹窗，支持点外关闭、Esc、返回触发点。正文优先显示勾选框和标题，已填写的时间才有标签。到期、跟进、执行时段各有文字标识，浅色和深色均可辨认。回到日历时保留日期、筛选和滚动位置。

## 哪条记录算数

**任务的标题、完成状态、排期属于 Markdown 正文。** 本地数据库承担空间查询，删除并重建该索引可以恢复这些字段。聊天回链属于本机私有会话信息，随会话备份保存；单独导出笔记时只带出笔记中已确认的任务。一个目标文档内批量添加可以原子保存。第一版每次确认面向一篇文档。

建议用一行标准 GFM 勾选项和行末带版本的专用注释。以下为两行独立任务的拟议源码：

```markdown
- [ ] 更新发布手册 <!--inkstone-task:v1 {"id":"0d49818d-0a4e-4721-ad70-1c8dc986ce62","due":"2026-11-27","slot":{"start":"2026-11-25T14:00:00+08:00","end":"2026-11-25T15:00:00+08:00","zone":"Asia/Shanghai"}}-->
- [ ] 等维护者回复签名问题 <!--inkstone-task:v1 {"id":"4bc8dd4e-ff44-40fe-bd68-5ea3363d04bc","waiting":true,"followOn":"2026-11-26"}-->
```

- 标题从清单第一段可见内容取得，保留链接、强调、子项、缩进及后续说明。仅第一逻辑行末、属于实际勾选项的有效标记会进入清单。代码围栏中的示例和引文中的转述默认不聚合。普通 `- [ ]` 保持原有行为。
- 勾选框是完成状态的唯一来源。`[ ]` 区分待办和等回复，`[x]` 为完成。完成后停止显示待跟进；重新打开时恢复原来的等待设置。移除跟踪只移除专用元数据，保留标题与勾选。
- 文档内使用稳定 UUID；存储和引用键是 `(spaceId, documentId, taskId)`。移动段落、改名和重新打开都按键定位，行号仅用于当前版本跳转。应用内复制一项时分配新 UUID；移动同一项保持 UUID。复制整篇文档得到新的 documentId，任务独立且不继承私有聊天回链。同文档的外部粘贴导致重复 UUID 时，在正文标明两处冲突，清单暂停这两项的写回，允许用户明确选择哪一处重新编号。
- 解析器只接受有限、已知类型的字段和有效 ID；限制注释字节数，拒绝重复 JSON 键、无效时间等。未支持的版本和字段可保留原样，带未知结构的条目先提供只读提示。移除标记后条目退回普通勾选项。打开旧文档无需自动改写或分配 ID。
- 这是 Alpha 的技术试验重点。当前富文本适配器会保护多数 HTML，行末注释可能让整个列表变为原始 Markdown 块。应在语法树的清单节点中识别这一种注释，将其映射为列表项属性，序列化时恢复；普通 HTML 仍走现有保护逻辑。先以源码、正文和分栏往返的真实样例证明可行，再做日历功能。[富文本适配器](../../src/rich/markdown.ts) · [清单工具栏](../../src/rich/toolbar.tsx)

## 日历的三个时间含义

| 字段 | 语义 | 修改方式 |
| --- | --- | --- |
| `due` 可空 | 截止日，无时间，属于本地民用日期。显示为「到期」，不占小时格。 | 改截止日期只写 due。 |
| `slot` 可空 | 一段已安排的执行时间。起止含偏移与 IANA 时区，结束晚于开始。首版每条任务至多一个时段。 | 在详情安排或移动时段，只改 slot。 |
| `followOn` 可空 | 等待他人时下次要跟进的日期。显示「跟进」。 | 收到答复时解除等待并清掉未来跟进；「完成」保留历史安排。 |

未填写日期或时段的任务留在清单。日历上可同时出现同一任务的周三时段和周五截止标记，共用同一任务 ID。任务与普通日程分别显示类型。「周四 15:00 一起开会」适合选择「建为日程」，进入已有日程编辑器，明确结束时间；缺少时长时保留草稿。第一版的日历为应用内联动。已有日程继续按原有规则导出 ICS，任务 ICS 与外部日历双向同步另行排期。

相对日期按消息产生时的日期与时区解释，在确认前显示绝对日期；缺少可靠时区或「下周找时间」一类表达保留待定。执行时段跨日、夏令时跳时和重复小时沿用现有时区校验，有歧义时由用户选实际时间。完成标记、改截止日、移动时段各有独立撤销行为。[现有日程模型与日期函数](../../src/content/calendar.ts) · [空间日历](../../src/calendar/ProjectCalendar.tsx)

## 聊天如何产生一条可靠的行动

1. **选来源。** 支持自己说的话和当前显示的完整回答。取得会话、回合、具体回答候选及原文范围。重新生成与分支会产生不同候选，原回链固定在当时版本。
2. **预览。** 选中文字转任务走本机路径，离线也能改标题、设日期。批量提取由用户点选后调用已配置的问答服务，默认只发送本轮选中的问答文字及解释相对日期所需信息。Beta 建议每次最多发送 8,000 个字符、返回 8 项；超过限制让用户另选一段。逐条核对引文。缺少对应原话、已明确完成或取消的动作排除；别人的承诺、尚未接受的求助和 AI 的建议默认不勾选。日期含糊时留空。服务失败仍可用手选。
3. **确认。** 每行显示「建议标题／依据原话／日期／目标」，来源用「你说」「AI 建议」明确责任。用户可改、删、只选一项。目标空间若已有外部工具读取授权，提示确认后的任务正文也属于该授权范围。提取与预览均不改文件。
4. **防重复。** 来源键绑定来源角色、会话、回合、回答候选（提问则留空）、原句范围与内容摘要。预览产生稳定的候选及操作 ID；同一确认重试复用这些 ID。跨次提取按来源键与行动短句匹配，精确匹配显示「已添加」。标题改写、同一句含多件事或另一份文档中的相似项只提供相似项选择，允许用户确实创建不同任务。
5. **回到依据。** 私有来源登记只存任务键、会话标识、范围和摘要，打开时复核权限、候选和原句。清除会话或撤销相应访问后，仍可读取自己已保存的任务，回链显示来源已不可用。将任务转成笔记不会自动复制整轮回答、网页正文或他人的联系方式。[现有回合和候选类型](../../src/assistant/types.ts) · [会话存储](../../src-tauri/src/assistant.rs)

## 技术落点和一致性

| 模块 | 现有入口 | 建议改动 |
| --- | --- | --- |
| 编辑与呈现 | [文档保存控制器](../../src/document/useDocumentPersistence.ts)、[富文本适配器](../../src/rich/markdown.ts) | 实现专用清单标记解析、属性编辑和局部写回。前端处理交互，Rust 在保存或重建索引时独立验证。两端使用同一套 Markdown fixture、日期样例和期望结果。 |
| 文档写回 | [Rust 文档保存](../../src-tauri/src/documents.rs)、[日历命令](../../src-tauri/src/calendar_commands.rs) | 新增按任务键和 expectedHash 修改特定字段的 Tauri 命令。核对空间、受管文档状态、文件类型、标记唯一性；改动构成最小补丁后进入现有文件锁、哈希比较与原子保存。避免在持锁时重复调用会取得同一锁的保存函数。 |
| 任务查询 | [已有 SQLite 日历投影](../../src-tauri/src/calendar.rs) | 为受管 Markdown 添加独立的、可重建的任务投影表，记录任务键、源哈希、行区间、标题、日期与状态，按空间及日期查询；日历组合任务投影与原有事件。打开工作区和保存后按哈希增量重建。 |
| 聊天来源与恢复 | [assistant.sqlite3](../../src-tauri/src/assistant.rs)、[备份校验](../../src-tauri/src/maintenance.rs) | 增量版本迁移加入来源映射和确认记录，以目标空间和来源操作 ID 设唯一约束，由同一事务预留任务 ID，抵御连点或并发确认。任务完成状态只从文档中读取。确认记录在写正文前持久化，包含目标键、预分配的任务 ID 与原版本。正文写入成功再标记完成。 |
| 搜索与外部工具 | [前端结构化切片](../../src/content/indexing.ts)、[Rust 关键词索引](../../src-tauri/src/db.rs)、[外部只读授权](../../src-tauri/src/external_access/mod.rs) | 搜索与问答可使用获准文档中可见的任务标题、状态和计划日期。给模型的切片剥离专用注释并保留对应原文行号。现有 CLI 的 read 仍按授权返回该版本的有限原文，原文中可含用户导出的排期；聊天回链和人员资料不写入注释。 |

**拟议 Tauri 接口。** 参数中的文档用空间 ID 和受管文档 ID 标识。Rust 决定允许的目录、实际时间区间与可写字段。前端用结果类型区分可重试操作。

| 命令示意 | 必要输入 | 结果或约束 |
| --- | --- | --- |
| `task_list` | 空间 ID、视图、日期区间、游标 | 返回该空间的投影行、源文档版本、下一游标和投影是否待刷新。 |
| `task_patch` | 任务键、expectedHash、字段补丁 | 哈希匹配且定位唯一才保存，返回新哈希与索引提示；否则返回 conflict、sourceGone 或 duplicateId。编辑器草稿先走同一编辑器事务；有分歧则显示 draftConflict。 |
| `task_propose` | 既有会话与回合标识、可选回答候选和选区 | 后端核对实际文本后产生预览项及候选 ID。用户编辑候选标题或日期时保留该 ID。 |
| `task_commit_batch` | 单一目标空间及文档、expectedHash、操作 ID、选中的候选 ID 与用户修订 | 首次成功返回每项的任务键与文件新哈希。同操作 ID、同请求重试返回原回执；负载发生变化需另一次操作。已存在的行动逐项返回 alreadyAdded，其余在同一篇文档内一次保存。 |

同一轮包含多件事时，按源文的最小行动短句分开预留任务 ID；同一句仍能拆成两个不同动作时，则使用各自冻结的候选 ID，不能只拿“这一轮”去重。撤销本次写入后，聊天里的老确认回执仍识别为已处理，绝不因网络重试自动复活；再次明确点击「重新添加」才创建新的操作 ID。取消预览无需保存私有映射。

**草稿与冲突。** 操作当前编辑文档时优先经同一编辑器事务修改，保留未保存的输入、选区和撤销栈，再等待保存确认。由清单或日历操作时若目标的本地草稿与磁盘分歧，先提示核对草稿。来自另一个窗口或外部编辑器的版本变化导致哈希失配时，保留用户的改动意图，重新读取后显示该任务前后的差别，由用户重试。禁止用旧整篇正文覆盖新文件。索引锁定时反馈「正文已保存，任务清单待刷新」，刷新按正文恢复。[现有保存实现](../../src-tauri/src/documents.rs)

**中断与恢复。** 同批候选写入同一文档，一次原子保存。崩溃后若有未结清的确认记录，重新读取目标文档并查任务 ID。全部在场且来源匹配时补完登记；仍为原版本且无任务时，可从预览重试；出现部分存在、已改稿、已删除或换空间时提示对照，不自动重放。普通本机任务即使会话库不可用也能正常使用。如果用户后来主动删掉已确认的任务，再次打开该候选时提供「重新添加」显式动作。执行清空会话、永久删除文档和备份恢复时分别验证映射清理及备份校验。旧文档与旧备份可直接读取；回退应用版本前保留升级前的可验证备份，另导出升级后的 Markdown。

**导入与撤销。** 从 Finder 导入、来源更新、还原历史和撤销都沿用文档入口生成投影。导入产生受管副本，任务编辑只回写该副本。再次导入沿用现有重复提示。来源更新检测到两边都有改动时走现有冲突处理。回收站文档立即从清单、日历和读取结果中移除，恢复文档后重建。当源文档被改名或移动，按文档 ID 和任务 ID 定位；路径不可访问就保留错误提示。

**把任务作为 AI 的输入。** 在任务详情点「帮我拆解」，应先预览将带入的标题、状态、日期和选中的笔记摘录，发送后返回建议。第一版用任务清单按日期和状态准确回答“今天有哪些待办”的筛选需求；若以后支持用户直接用问答问数量，应由本机查询授权空间的任务投影，再交给模型表达。正文的语义检索适合找相关工作，不能保证清点齐全。

以下为版本目标，待原型和真实用户走查验证。

| 1.1.0-alpha.2 | 截止日、执行时段、等回复与跟进、应用内日历双向写回 | 周三移动至周四，周五截止保持不变；无日期项、到期标记不会占时段；跨月与夏令时可解释；草稿冲突、回收、还原和索引重建均通过。 |
| 1.1.0-beta.1 | 手选转任务、模型批量提议、确认和来源跳转 | 用正/负例测试承诺、建议、已办、已取消、相对日期和一轮多项；分别统计动作识别准确率、漏项、日期误定率。重复点击、取消、断网、重生成和崩溃恢复不重复落盘；未确认写入和跨空间读取均为零。 |
| 1.1.0 | macOS 原生验证、备份恢复、真实笔记试用、用户手册 | 建议邀请 5 名试用者，至少 4 人在无指导下独立完成「从复盘选两件事 → 保存正文 → 安排其中一件 → 日历回文 → 完成」；预先区分阅读用时与操作用时，记录“一分钟建两项并排期”完成数和每次求助。出现误覆写、来源越界、重复创建或任务不可找回时保留 beta。 |

**提取评测单列。** 建议在模型调优前固定至少 40 段合成对话，按行动、责任、日期和对应原句逐条标注。Beta 的建议目标为可创建候选的精确率至少 90%、已明确承诺的行动召回率至少 80%、所有预填明确日期均与原话一致；同时报告分子、分母以及误判案例。两人对有歧义的标注先达成一致。模型提取若未达标，可交付手选转任务，批量提取继续停留在实验入口，用户实际完成整条流程仍需另行验证。

在 Alpha 前保留小型对照样例，把同一份文档交给现有编辑器和新解析器，确认普通勾选列表的样式、打字延迟与内容往返。性能评测另用含 1,000 篇笔记、5,000 条任务的合成空间，记录首次建索引、二次打开、列表筛选、单文档保存的中位数与 P95，注明机型和是否后台重建。先测基线，再决定是否需要增量渲染或分页。任务重复规则、跨人派单、自动发信、AI 后台执行、提醒推送及 CLI 写操作留给独立需求评估。
