# Inkstone v0.7.0-rc.5 候选交付记录

2026-11-07。此次候选将文档保存职责从主界面抽出，并修复生成期间下一问的草稿写入。公开源码预览仍为 v0.7.0-rc.4。日常安装入口和候选构建位置见[本机管理说明](LOCAL-INSTALLATION.md)。

## 工程准备

- 分支修改用 `npm run verify:changed` 获取定向反馈。GitHub 在 PR、main 推送和手动请求时运行 `verify`。已覆盖的纯文档 PR 运行文档检查，main 和代码变更运行完整检查与原生构建。
- Cargo 缓存按 macOS、SDK、编译器、目标及锁文件区分，main 保存缓存，PR 只恢复。构建后的签名校验继续执行。已用 actionlint 和临时 Git 历史覆盖纯文档、混合代码、重命名、未知基线与主分支路径。托管缓存命中和提速幅度需要实际 GitHub 样本。[GitHub 缓存参考](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching)
- `useDocumentPersistence` 管理正文的保存、恢复草稿和自动保存计时，工作区切换和页面协调由现有入口负责。现有工作日志分别记录检查与构建用时。

## 草稿持久化

生成期间的自动保存绑定会话和当前请求。后端仅在对应候选仍在生成时写入，并更新会话版本。生成先结束时，普通队列用最终版本保存剩余草稿。重新生成现有回答会保留已输入的下一问。如果用户在问题草稿保存期间停止，应用在发送前复查停止状态。继续沿用现有会话数据库结构。

测试覆盖两次输入的顺序、跨空间和错请求拒绝、结束后阻止晚到写入、停止保留草稿，以及重新生成保留输入。生产 React 界面使用隔离的合成协议复跑编辑、回收站、问答、来源、停止和重开。定向浏览器用例在候选仍在生成时核对草稿已保存，停止后重载并从原会话取回。

## 依赖与第三方声明

Zstandard 采用 0.13.4 和 zstd-safe 7.4.0。514 个 registry 包的 OSV 复扫不再命中这两个包，锁图仍有 fxhash、glib 和 proc-macro-error 条目。Apple Silicon 依赖图中仍有 fxhash，glib 和 proc-macro-error 位于目标外。独立文本通过上游版本、源码比对或发布标签补入 sqlite-vec、jieba-macros 和 Apple Silicon Rolldown 绑定，20 处独立文本缺口降至 17 处。记录见[许可清单](../licenses/manifest.json)。

当前 npm 审计的五项低风险条目来自同一个 KaTeX 公告的依赖传播。现有 Mermaid 与数学解析链声明的版本范围无法容纳该修复，需要单独验证渲染栈升级。Rust 的未维护包和其他平台条目继续按目标依赖图复核。[KaTeX 公告](https://github.com/advisories/GHSA-238p-pmpm-9mq7)
