# Security policy

Inkstone is an experimental local application. Only the current source preview is maintained; there is no security SLA or supported production release line yet.

Do not post a working exploit containing credentials, personal documents or a real backup in a public issue. Once the repository is published, use its GitHub **Security → Report a vulnerability** channel when enabled. Until a private reporting channel is enabled, avoid sending sensitive exploit material through public issues. Repository owners should enable private vulnerability reporting and secret scanning before announcing the project.

Model requests use the endpoint configured by the user. Embedding sends selected text chunks, reranking sends the question and candidate snippets, and generation sends the question and selected evidence. Wiki compilation can send excerpts from the explicitly selected managed documents to the configured chat model. Local-only keyword retrieval makes no model request. Keys are stored through macOS Keychain and excluded from document backups. The app checks permissions, scope and source versions independently of document text and model output.

Web search is disabled by default and uses a separate user-configured Brave Search API key. When enabled, the chat model proposes a search using only the current question. The app applies scope and sensitive-pattern checks before sending a public query to Brave. It fetches candidate pages separately over HTTPS and limits destination, redirects, content type, body size and time. A site's publisher can observe the page fetch. The app uses extracted page text for the current answer and records web citation metadata for later inspection. The checks cover defined patterns, so keep confidential details out of questions intended for public search.

Scoped generation can include limited previous questions and enabled presentation preferences. Standalone chat can also send an excerpt of the previous answer as conversational context for editing or follow-ups. Evidence comes from the sources selected or retrieved for the current turn. Companion stories and experience cards stay separate. Conversations, local attachment copies, source records, drafts, Wiki and companion data are stored locally. Backups can include conversation attachments, quoted sources and Wiki state. Treat backups and exports as private files. Deleting content in the app leaves previously exported files and backups intact. The optional companion uses no separate model call.

The app constrains Markdown/structured blocks, renderer frames and chart data. Citation identifiers and numeric presence are checks, not proof of semantic truth. Review AI output before using it. Backups validate paths, hashes and database contents and restore to a new directory for preview.

Known dependency findings and the exact scope of checks are recorded in [the public readiness assessment](docs/GITHUB-READINESS-v0.7.md). Passing a scanner does not establish absence of vulnerabilities. Development servers listen on loopback; do not expose them to an untrusted network.
