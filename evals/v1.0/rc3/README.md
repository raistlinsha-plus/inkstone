# RC.3 中文问答开发对照

22 个问题取自 8 篇新写的虚构 Markdown。标注由 AI 在运行检索、选句和生成器之前直接阅读这些资料完成，尚待独立人工复核。开发人员可以阅读这套题。原有 52 题、封存答案和用户文档均未用于编题或标注。

[20 道主问题及逐小问标注](questions.json)保留首轮冻结的文件，另以[两道多义指代题](ambiguous.json)覆盖无法唯一指向一本记录的场景。冻结的[摘要清单](fixture.sha256)本身的 SHA-256 为 `ef9e3d9c968723c5b12e74b044596660b520cd5c38a7f92b3722c24cc80982ee`。Rust 运行器在导入前校验清单及文件。题型为可答 8、部分可答 4、冲突 1、可解析追问 3、缺证 4、指代多义 2。前四类合计 16 题，包含 27 个有据答案点。

每个答案点给出一个或多个等价的「文件名#行号」和可接受值示例。`missing` 写明哪些信息仍须承认缺失或追问，`gap_context` 记录原文能够明确说明的空栏、分歧或多义情况。`skip` 逐行注明相似片段为什么不能支持该答案。一行文字有时能证明信息待定，同时不能作为确定答案。找不到原文依据时允许黄金上下文为空。

离线分数只衡量原文是否完整出现，不评定回答内容。8 篇短文各占一个索引块，候选库很小，因此这套题适合定位证据筛选损失；大库召回能力须在更大的独立集上测。该开发实验仅测 BM25。应用端分支、历史来源身份、权限切换及向量/重排回归由各自测试覆盖。

## 怎样复现

在仓库根目录执行。若当前 shell 未加入 Rust 工具链目录，可用 `$HOME/.cargo/bin/cargo`。每次使用新的输出文件名。临时资料库与输出报告彼此独立，报告路径必须为绝对路径。

```sh
run_dir="$(mktemp -d)"
INKSTONE_RC3_DEV_REPORT="$run_dir/offline.json" cargo test --locked --manifest-path src-tauri/Cargo.toml --lib evaluation_rc3::offline_causal_dev -- --ignored --exact
python3 evals/v1.0/rc3/report.py "$run_dir/offline.json" > "$run_dir/summary.json"
```

真实生成对照使用设置中已启用、地址绑定的问答服务。以下显式实验只在隔离状态里允许将合成候选发送给同一服务进行选句，不写入用户设置。每题同一 BM25 候选分别经过 RC.2 筛选、RC.3 实际空间问答证据组装、直接取标注原句。三臂使用同一轮原始问题、固定上文、生成器、回答系统提示与字符预算，送入不同的原文。为只改变证据，在三臂中都不追加 RC.3 专用的小问提示。即使一臂上下文为空也调用生成器；正式应用可在证据为空时直接返回。因此这是证据选择的生成对照，产品端到端表现另行测量。追问用相同上一轮用户问题帮助检索，上轮答复只为生成器说明所指对象。输出中的哈希可核对两类系统提示的实际版本。

```sh
run_dir="$(mktemp -d)"
INKSTONE_RC3_DEV_LIVE=1 INKSTONE_EVAL_KEYCHAIN_WAIT_SECONDS=300 INKSTONE_RC3_DEV_REPORT="$run_dir/live.json" cargo test --locked --manifest-path src-tauri/Cargo.toml --lib evaluation_rc3::live_causal_dev -- --ignored --exact --nocapture
python3 evals/v1.0/rc3/report.py "$run_dir/live.json" --blind "$run_dir/review" > "$run_dir/live-summary.json"
```

每次完整真实实验共 66 次回答调用，最多另有 22 次按需选句逻辑调用。服务层对回答可能重试。原始报告分开记录调用返回原因、选句次数、选句耗时和各臂生成耗时；汇总脚本按最近秩给出生成 P50/P95 及各臂路径 P50/P95。实际检索臂的路径时间为同一次共享检索、该臂证据组装和该臂生成耗时之和，黄金臂为直接取原句与生成耗时之和。服务出错或返回截断会记为未完成。一个进程中集中测试时可把同一进程内的凭据读取器传给 `evaluation_rc3::live_with_settings`。生产设置、凭据和私人文档不写入报告。

## 回答盲审

评审者只拿 `blind-review.json`，配合这套公开合成资料按题核查。每条提供原问题、固定上文、匿名答案、实际编号的来源和预标条件。每个答案点分别勾选内容正确和紧邻引用支持。再按题评断缺口是否说明、无据题是否武断给值、有据题是否一概拒答、各关键断言及其有据数量、整题严格通过和严重错误，并写下理由。服务失败的答案记整题未通过，有据答案点记未完成；在缺证题上服务失败同样不能算正确拒答。部分可答题至少答出已知项并明确局部缺口才能整题通过。冲突题要把两个数值正确归属并保留未裁定状态；多义题可问清对象或分别给出两个有据选项。仅匹配数值不算正确引用。

评分者完成后，由保管映射的人运行下列命令。脚本核对答卷和来源未改动，汇总误拒、无据误答、关键断言引用支持及「前 8 段已有证据」分母上的正确且有据点数。人工评审、独立 AI 复核和自动取齐检查须各自具名。

```sh
python3 evals/v1.0/rc3/report.py "$run_dir/live.json" --score "$run_dir/review/blind-review.json" "$run_dir/review/keep-from-reviewer.json" > "$run_dir/scored.json"
```
