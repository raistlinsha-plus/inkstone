# v0.7.2 Wiki 离线回归

使用四份合成文档、两篇预置 Wiki 和八个自编场景，对比本地 BM25 与 BM25 加 Wiki。两组使用相同的查询、文档范围、证据判断和上下文构造。Wiki 页通过实际存储和发布校验入库。每条 Wiki 命中的版本哈希、行号和文字均回到当前文件验证。样本与实现由同一开发过程编写。

| 指标 | BM25 | BM25 加 Wiki |
| --- | ---: | ---: |
| 预期候选原文片段覆盖 | 4/6 | 6/6 |
| 符合条件的必要原文片段进入回答上下文 | 4/4 | 4/4 |
| 必要原文齐全的可回答场景 | 3/3 | 3/3 |
| 应保持空上下文的场景 | 5/5 | 5/5 |

「预期候选原文片段」包含可回答场景的四条原文，以及仅应停留在候选区的两条原文。后两条分别来自 Wiki 别名和含有虚构授权码的生成标签。Wiki 帮助找到了候选原文，保守的证据判断没有将它们加入回答上下文。测试另验证当前文档范围、Wiki 未授权文档、无匹配查询，以及原文更新后旧版本不再出现。

```sh
cargo test --manifest-path src-tauri/Cargo.toml --locked --lib wiki:: -- --nocapture
```

运行结果为 3 项 Rust 测试通过，其中一项执行上述八个场景。另两项覆盖未授权来源隔离、已处理内容跳过、服务配置变更，以及原文行范围和篡改校验。

设计要求的 96 道新题包括 32 道调参题和 64 道独立盲测题。本次八个场景属于内部回归。向量和远程重排、实时网页、真实模型编纂、生成答案的引用支持率、延迟及费用需要分别测量。本样本观察到的提升是候选覆盖，必要原文进入回答上下文的覆盖保持持平。
